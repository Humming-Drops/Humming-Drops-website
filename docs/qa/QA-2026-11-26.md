## Before deploying

1. Set a private `SESSION_SECRET` (32+ characters). The app now refuses to sign anyone in without it. Rotate it on any environment that used a committed default.
2. Run `npm run db:migrate` (data-only migration `0009`).
3. Set `NEXT_PUBLIC_APP_URL`, `RESEND_API_KEY` and `MAIL_FROM`. Without a mail provider, password reset reports success but sends nothing.

## Open: needs an owner or client decision

- Logout and password reset do not revoke existing sessions. Needs a `session_version` column and a deploy step that runs migrations.
- Deploys do not run migrations, and `/api/health` does not detect an unmigrated database.
- Terms and health-programme consent is checked in the browser only; storing it needs final legal text and a version.
- Legal text for `/terms` and `/privacy`; contact address and map.
- Unconfirmed claims kept by earlier decision (7:30 AM, closed Sundays, triple-washed, doctor-certified, founder quote) conflict with ADR-007.
- Other unconfirmed copy: "Cold-Pressed Juices", "food-grade sealed", "picked at dawn", "chilled box", hummingbird companion / virtual garden.
- Generic "Subscribe" buttons preselect Standard.
- Pause length limits and cut-off time.
- Whether `CLAUDE.md` (Supabase, Vercel, shadcn) should be updated to match the code.

## Open: engineering

- Row Level Security is enabled only on `password_reset_tokens`.
- `drizzle/meta` has no snapshots, so `db:generate` and `db:check` cannot diff.
- No CSP or HSTS; `/api/health` exposes Node version and memory.
- No Origin check on writes (SameSite=Lax limits this to same-site).
- Last-Super-Admin guard is not transactional.
- Pending or cancelled accounts can still edit delivery notes through the API.
- README, runbooks and tracker still describe Clerk, Supabase, Vercel and an oats plan.
- About 26 MB of unused video in `public/`; hero video is 5.9 MB.
- Unit tests exceed the 5 s default timeout on a low-memory machine.
